# eidos v0.5.0

A trustworthy standalone Windows indexer that can also run as a small,
explicitly enrolled private fleet. Standalone remains a complete, supported
topology; the fleet is experimental and off until a node is enrolled.

## Downloads

- `eidos-v0.5.0-setup.exe` - the setup. Installs eidos and, when chosen
  under *Advanced: profiling collector*, the
  observatory collector as a separate service.
- `eidos-v0.5.0.msi`, `eidos-collector-v0.5.0.msi`,
  `eidos-collector-v0.5.0-setup.exe` - administrator and fleet artifacts.
- `*.sha256` - checksums of every asset.

Every executable, MSI, Burn engine and bundle is signed; the checksums are
generated after signing and verified independently by the release job.

## What is new

- **Unified setup.** One signed installer for the core and the optional
  collector; the two stay separate services with separate data
  directories, identities, ACLs, and removal. A host set up with the
  separate collector package upgrades in place without rotating its study
  key or losing its spool or configuration. Uninstall keeps both products'
  data unless asked; purging one product's data leaves the other's alone.
- **Private fleet (experimental).** `eidos fleet central --listen`,
  `eidos fleet invite`, `eidos fleet enroll` set up one central and its
  nodes. Nodes replicate catalog metadata continuously over mutual TLS with
  pinned per-node certificates; either side may dial; central search
  returns the union with the origin host, source, freshness and
  completeness on every result. See [docs/fleet.md](../fleet.md) and
  [ADR-0023](../adr/0023-experimental-fleet-boundary.md).
- **`host:` queries** resolve real hosts (by name or id) instead of a
  single fixed host.
- **Observatory:** the collector's own process is classed `collector`,
  separable from the indexer and from the workload.
- `eidos bench chunking`: the content-transfer bakeoff
  ([ADR-0024](../adr/0024-content-transfer-bakeoff.md)).

## Known limits (the experimental fleet boundary)

- Content is **not** replicated. Central search answers metadata queries
  over the union; content queries report `ContentNotReplicated` per
  replicated source and must be run on the origin node.
- One central; no discovery, relay, NAT traversal, failover, credential
  rotation, or multi-user authorization. Enrollment is command-line only.
- The sync wire protocol is stable only within its version negotiation
  (`1`); mixed versions fail closed with no data loss.
- Directory aggregates of replicated sources are recomputed periodically
  (about once a minute after changes) rather than incrementally.
- A collector selected beside a per-user core still installs as a per-machine
  LocalSystem service and therefore requires administrator approval.
- macOS/Linux have no fleet role in this release.

## Upgrading

Run the new setup: it upgrades in place and keeps settings, data, the
fleet identity (`fleet/` under the data directory), enrollment, cursors,
and the collector's study key. Upgrading a busy host stops both services
promptly and restarts them. If the eidos service uses a named Windows account,
interactive setup asks for its password again; unattended upgrades must pass
`EIDOS_SERVICE_PASSWORD`.

## Rolling back

1. Uninstall v0.5.0 with the setup or *Settings › Apps*, keeping the data
   (the default).
2. Install the previous release. The catalog schema migration added by
   v0.5.0 (fleet tables, history chain) is additive; a previous release
   ignores those tables, and the search index is rebuilt automatically if
   its generation is behind.
3. A node that was enrolled stops replicating after rollback; the central
   keeps the last applied state and reports the node offline. Re-enrolling
   after a later upgrade is a new epoch.
